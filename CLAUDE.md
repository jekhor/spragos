# CLAUDE.md

Spragos — тренажёр литовской грамматики: упражнение «перетащи слово в пропуск». Интерфейс и комментарии на русском, учебный материал на литовском. Пользовательская документация и формат базы описаны в README.md.

## Команды

```bash
python3 serve.py              # http://localhost:8000/ (--port, --host 0.0.0.0 для телефона)
node --test                   # все тесты (tests/*.test.mjs)
python3 build.py _site        # статическая сборка для GitHub Pages
```

Сборки и npm-зависимостей нет. Сервер работает на stdlib Python, фронтенд написан на чистых ES-модулях без фреймворков.

## Архитектура

- `serve.py` раздаёт `web/` как корень, `/data/...` берёт из `data/`, а `GET /api/files` возвращает рекурсивный список `data/**/*.txt` и `data/**/*.md`. Заголовок `Cache-Control: no-cache` стоит намеренно: правки базы видны после обычной перезагрузки страницы.
- Публикация: https://jekhor.github.io/spragos/. Workflow `.github/workflows/pages.yml` при push в `main` прогоняет тесты, собирает сайт через `build.py` и деплоит. На статическом хостинге нет `/api/files`, поэтому `app.js` при его отсутствии читает `data/index.json`, который генерирует `build.py`. Все пути в коде должны оставаться относительными: сайт живёт в подкаталоге `/spragos/`.
- Предпросмотр ссылки (Telegram и т. п.): метатеги Open Graph в `web/index.html` с абсолютными адресами `https://jekhor.github.io/spragos/`, картинка `web/og-image.png` генерируется `tools/make_og_image.py` (Pillow, Noto Sans). При смене адреса сайта обновите и метатеги.
- Браузер сам скачивает и разбирает все файлы тем. Отдельного шага сборки или индексации нет, поэтому новая тема — это просто новый `.txt`.
- `web/js/parser.js` и `web/js/round.js` не используют DOM: их импортируют и браузер, и node-тесты. Логику разбора и сборки раунда держите там, а не в `app.js`.
- Подтемы: строка `@subtopic: Заголовок | пояснение` в файле темы; `parseTopic` кладёт их в `topic.subtopics` (`key` = `файл#Заголовок`), у каждого задания `item.subtopic` = этот ключ. `settings.topics` хранит файлы тем и ключи подтем; файл темы с подтемами означает «все подтемы» (`toggleSubtopic` в `app.js` сворачивает полный набор подтем в файл). `applySelection` в `round.js` превращает выбор в список тем, у частично выбранной темы — копия только с выбранными подтемами (`partial: true`). Статистика пишется по `statsKey`: ключ подтемы или файл темы.
- Тренировка одного слова: `settings.lemma` — нормализованная лемма-подсказка. `poolFor` отбирает задания с ней, в `buildRound` активны только её пропуски, а `unit.slots` хранит для каждого пропуска задания id или `null`. Для `null` `renderRound` показывает готовый ответ (`.given`). Список слов строит `listLemmas`; темы с `@word-practice: off` (существительные) в нём не участвуют, и если других тем не выбрано, строка «Слово» скрыта. Общий `@distractors` темы в этом режиме не используется.
- `round.js` подбирает задания под целевое число пропусков, с весом по прошлым ошибкам. Лишние формы берутся в таком порядке: явные из `{…|…|a, b}`, затем ответы других пропусков темы с той же подсказкой-леммой, затем `@distractors`. `buildRound` принимает `rnd`, чтобы тесты были детерминированными.
- `dnd.js` реализует перетаскивание на Pointer Events. Клики и тапы обрабатывает `app.js` через обычный `click`. После перетаскивания глушится только клик в точке отпускания (`swallowClickAt`). Не заменяйте это глобальным флагом: иначе теряется следующий клик пользователя.
- Два режима раунда (`state.round.mode`): `drag` — плашки из банка (`placement`, `layoutChips`), `type` — поля ввода (`typed`: gapId → текст, `layoutTyped`). В режиме ввода на месте банка панель литовских букв; `buildRound` вызывается без лишних форм. Проверка в обоих режимах — `isCorrect` из `round.js`: регистр и пробелы не важны, диакритика важна.
- `app.js` хранит состояние раунда в `state.round` (`placement`: gapId → chipId, `status`: gapId → correct/wrong). `layout()` переносит DOM-узлы плашек туда, где они должны быть по состоянию, поэтому после любого изменения состояния достаточно вызвать `layout()`.
- Справки (`data/*.md`) рендерит собственный минимальный Markdown-рендерер `web/js/markdown.js`: внешних библиотек нет, весь HTML экранируется. Тема получает справку из `@reference` или из `.md` с тем же именем (`resolveRef` в `app.js`). Окно справки — это `<dialog id="ref-dialog">`.
- Экраны (`.screen` в `index.html`) переключает `show()` в `app.js`: home, setup, round, refs, stats. Текущий экран отражается в адресе (`/` — главная, `#setup`, `#round`, `#refs`, `#stats`) через `history.pushState`, поэтому работают кнопка «назад» и перезагрузка; раунд после перезагрузки не восстанавливается, вместо него открываются настройки.
- Лицензии: код — MIT (`LICENSE`), материалы `data/` — CC0 (`LICENSE-CONTENT.md`), кроме фраз из учебников. Файл лицензии материалов нельзя класть в `data/`: любой `.md` там считается справкой.
- Языки интерфейса (ru, be, uk, en): словари и `detectLang`/`t`/`plural` — в `web/js/i18n.js` (без DOM). Статические тексты `index.html` помечены `data-i18n*` и заполняются `applyStaticTexts()` в `app.js`; всё, что `app.js` рисует сам, берёт строки через `i18n.t`. Выбранный язык — `settings.lang` (пусто — по `navigator.languages`). При смене языка `changeLang` перерисовывает текущие экраны, раунд не сбрасывается. Переводы тем — строки `@title.be`, `@group.be`, `@description.be`, `@subtopic.be` (поле `i18n` у темы и подтемы, читать через `localized()` из `parser.js`); переводы справок — файлы `имя.be.md`, их подцепляет `loadTopics` к `имя.md` (`ref.translations`). Ключи подтем и статистики не зависят от языка. Сообщения об ошибках разбора базы не переводятся. Метатеги Open Graph остаются русскими: краулеры не исполняют JS.
- `stats.js` хранит статистику и настройки в localStorage. Все обращения обёрнуты в try/catch. Статистика пишется только при первой проверке раунда.

## База заданий (`data/*.txt`) и справки (`data/*.md`)

- Полные правила генерации заданий — в `MATERIALS_GUIDE.md`. Он рассчитан на передачу в другую LLM-сессию, поэтому при изменении формата или парсера обновляйте и его.

- Синтаксис пропуска: `{ответ/альтернатива|подсказка|лишние, формы}`. Заголовки: `@title`, `@group`, `@description`, `@distractors`, `@hints: always`, `@reference`, `@word-practice: off`, `@subtopic`.
- У каждой темы и справки должны быть переводы на все языки интерфейса (be, uk, en): `@title.xx`, `@group.xx`, `@description.xx`, `@subtopic.xx` (если в заголовке подтемы есть кириллица) и `имя.xx.md`. Это проверяет `tests/i18n.test.mjs`.
- Прогоните `node --test` после любой правки базы. Тесты проверяют:
  - синтаксис каждого файла;
  - что каждый ответ — форма своей подсказки (`tests/forms.test.mjs`);
  - что тривиальных пропусков (ответ = подсказка) не больше 10% темы и предложения не повторяются.
- Парадигмы для этой проверки лежат в `tests/paradigms.mjs`: местоимения, числительные и прилагательные (порядковые числительные — как прилагательные), существительные (`nounForms`). Тип склонения существительного тест берёт из номера в начале заголовка подтемы («1. …»), но только для файлов из `NOUN_FILES` в `tests/forms.test.mjs`; в остальных темах (прилагательные, числительные) номер подтемы — просто порядок. Леммы других частей речи пока пропускаются. Для новой темы (глаголы) добавьте туда их парадигмы, тоже сверенные с учебниками.
- Валидатор проверяет только существование формы. Правильность выбранного падежа и естественность предложения он не проверяет.
- Литовские формы сверяйте с таблицами учебников из `/home/jek/work/Lithuanian/*.pdf` (текст извлекается через `pdftotext`). Самые удобные источники:
  - `2014_Žingsnis_I.pdf` — приложение с таблицами местоимений, числительных (количественных, собирательных, порядковых) и окончаний существительных всех пяти склонений;
  - `petrasiuniene_e_langas_i_lietuviu_kalba.pdf` — местоимения, приложение с таблицами склонения существительных;
  - `Complete_Lithuanian.pdf` и `Press_I_J__Ramoniene_M_-_Colloquial_Lithuanian_-_2011.pdf` — прилагательные, выражение времени.
- **Не используйте материалы Šaunuolė** (`Saunuole-*.pdf`, saunuole.lt): ни таблицы, ни примеры, ни структуру объяснений. Их авторы могут быть против. В репозитории их не должно быть.
- Ответ должен однозначно следовать из контекста предложения. Где по смыслу подходят два слова, указывайте оба через `/`. Если однозначность без подсказки недостижима (прилагательные, числительные), ставьте в теме `@hints: always`.
- Пропуски, где ответ совпадает с подсказкой (`{du|du}`), полезны в небольшом количестве: 2–3 на слово, не больше 10% темы.
- Таблицы в справках сверяйте с теми же учебниками, что и задания. Тест в `tests/markdown.test.mjs` проверяет, что у каждой справки есть заголовок `# …` и что все `@reference` указывают на существующие файлы.
